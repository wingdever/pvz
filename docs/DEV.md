## 0. 一条铁律

**它必须能被无头运行证明。** 一个跑不到 `self-check PASSED` 的实现，不管看起来多像，都不算这个游戏。

由此推出两条工程习惯：① 每个模块自带一段自检，并打印自己的日志前缀（`docs/ARCHITECTURE.md` §5）；
② 每批改动都以"这条命令跑完还是全绿"收尾，而不是以"我觉得写完了"收尾。

## 1. 每批怎么干（工作节奏）

- **一批只做一件事**，批次边界就用 §3 的里程碑。不要把两个里程碑混在一批里。
- **每批结束跑 §2 的验收命令**，`FAILED` 为 0 才算这批完成。
- **每条新判据都要反向验证一次**：故意把那一格数据改坏，确认它变红、且不产生 SCRIPT ERROR，再改回来。
  "绿了"只说明判据没报警；"先红过"才说明它真的在看这件事。
- 改动要留下**为什么**的注释，并带批次标记（如 `[M7]`），方便下一批接手时读懂动机。
- **数值只改表与数值表文件**，不在调用点写死（`docs/ARCHITECTURE.md` §2）。
- **先跑通闭环，再扩内容**：3 株植物 + 1 种僵尸就足以构成可玩的 MVP，不要一上来就铺 50 个单位。
- **无头证明不了的事不要硬塞进验收**：渲染、手感、听感单独列进 §7 的目视清单，攒一批一次看。
- **每批把读数记进 §6 的台账**。读数变了不是问题，**说不清为什么变**才是问题。

## 2. 验收命令

```bash
# 1) 启动自检（跑完自行退出，不要用外部 timeout 强杀）
godot --headless --path . --quit-after 240 > /tmp/pvz_check.txt 2>&1

# 2) 读结果（另开一条命令）
grep -c PASSED /tmp/pvz_check.txt
grep -c FAILED /tmp/pvz_check.txt

# 3) 战斗探针：需要"节点已经建好"才能跑的那一批断言
godot --headless --path . --quit-after 20 -- --battle=Lawn_1_2 > /tmp/pvz_battle.txt 2>&1
```

- **通过标准只有一个：`FAILED` 一个都没有。** 不是某个固定读数——判据行数会随内容增长。
- 限时用引擎自己的 `--quit-after`（按帧数），**不要用外部 `timeout` 强杀**：被强杀的进程退出码、
  缓冲与文件状态都不可信，读出来的数是假的。
- **热重载边界**：改 `.csv` / 关卡 JSON 用游戏内的重载键就能看到；改 `.gd` 要重启；改素材要重新导入。
- **新写的全局 `class_name` 在编辑器重扫工程之前是看不见的**（`docs/ARCHITECTURE.md` §1.3）。
  纯无头也能完成这次扫描：`godot --headless --path . --import --quit-after 5`；
  或者干脆按 `docs/ARCHITECTURE.md` §1.3 的约定——搬出来的小模块不写 `class_name`，用 `preload` 消费。
- **命令由谁跑**：谁实现了这批谁自己跑。如果实现者是 AI 而宿主环境限制它执行命令，
  就把上面三条原样交给人类执行，并把输出贴回来再继续。

## 3. 里程碑 M0–M17

每个里程碑的"完成"= **§2 的命令跑得过，且该行点名的自检前缀都在打印**。

> **[B1–B2c] 乱斗模式的分批计划不在这张表里**——它属于第二种玩法（实时那一支），批次 B0–B6 与每批的
> 完成判据写在 **`docs/prompt/BRAWL.md` §13**（那是 `PROMPT.md` 的子文档）。这里是那份表的位置说明，
> **不是它的第二份副本**：要改分批计划，改那边。
"目视项"= 无头证明不了、要等开窗口时一起看的东西（见 §7）。

### M0 · 工程骨架

- **做什么**：`project.godot`（`docs/ARCHITECTURE.md` §1.1 逐键）、**宿主外壳场景** `scenes/main.tscn`、
  两个 autoload（`Boot` / `Game`）、启动横幅与引擎版本核对、无头验收通道（重定向 + `grep`）。
  ⚠ **[P107d] 这一步的形状后来变过一次**：M0 当年 `main.tscn` 是仓库根下的一个**裸 `Node2D`**，
  三层 UI 由 `Game._bootstrap()` 在运行时建；现在外壳是**场景声明的**（`MenuLayer` + 常驻 `Menu` +
  `GardenLayer`），`Game` 只**认领**它们（见 `docs/ARCHITECTURE.md` §3.3 / §3.4）。
  里程碑记录描述的是**当年做到哪一步**，不是今天的形状——今天的形状以那份文档为准。
- **交付物**：工程能被无头启动并自行退出；日志里能数到 PASSED/FAILED。
- **必须出现的自检**：启动横幅 + 第一条自检（哪怕只有一条判据）。
- **别做**：不要在这一步就加 autoload 之外的全局单例，也不要写 `[input]` 动作表。

### M1 · 数值表 + 棋盘 + 单位基类（色块）

- **做什么**：`Balance` / `BalanceUI` 两份数值表；`Grid`（9×5）；`Unit` 基类；**3 株植物 + 1 种僵尸**，
  全部用色块占位。
- **必须出现的自检**：`[Layout]`（几何不变式）、`[SelfCheck]`（回合/放置的基本接线）。
- **目视项**：草坪格子是否对齐、色块大小是否合理。

### M2 · 回合状态机 + AP 经济

- **做什么**：`PROMPT.md` §3.1 的显式枚举 + 单入口推进；§3.2 的 AP；可复现的判定顺序（按格坐标）。
- **必须出现的自检**：**阳光恒等式**常驻判据；判定顺序的判据。
- **目视项**：回合推进的观感（这阶段还没有动画，重点看日志是否符合预期）。

### M3 · HUD 与卡片种植

- **做什么**：上下两条（上 HUD、下卡片与 END TURN）、点卡片再点格子种植、END TURN 结算。
- **必须出现的自检**：HUD 读数与内部状态一致（阳光/回合/阶段/额度）。
- **目视项**：卡片不撞 END TURN；六种窗口比例下都不重叠（这也要等 M7 的 `Layout` 才严谨）。

### M4 · 表现层：特效与射弹

- **做什么**：`Fx`（火星、飘字、震屏，独立层且 z 序固定在单位之上）；`Projectile` 与恒速飞行的豌豆弹。
- **必须出现的自检**：`[Fx]`。
- **目视项**：出膛点是否在炮口、命中瞬间有没有火花、快进时是否跳过动画。

### M5 · 关卡数据 + 难度 + 结算 ⇒ MVP

- **做什么**：`LevelData` / `LevelList` / 关卡 JSON（`PROMPT.md` §5）/ 三档难度（`PROMPT.md` §3.7）/ 结果面板与重开。
- **必须出现的自检**：`[Levels]`、`[Diff]`。
- **到这里的验收**：能给一个外人玩 3 分钟，他能看懂发生了什么。

### M6 · 三件工具

- **做什么**：铁锹 / 手套 / 锤子 + **充能模型**（起始 0、每回合 +1、到阈值才可用、用掉归零）。
- **必须出现的自检**：`[SelfCheck] tools` 段，尤其"**被拒绝什么都不消耗**"。

### M7 · 几何：纯函数 + 可审计

- **做什么**：`Layout.compute_for()` 纯函数、`refresh()` 落进静态变量、`_audit()` 带容差断言不变式，
  并对 5:4 / 4:3 / 16:10 / 16:9 / 2:1 / 21:9 **六个采样比例**逐一验几何（不需要真开窗口）。
- **必须出现的自检**：`[Layout]` 六比例全 OK。
- **为什么早做**：它是后面所有页面布局的地基，晚做等于把同样的坐标算法抄六遍。

### M8 · 前端与窗口策略

- **做什么**：主菜单 / 关卡列表 / 设置三页 + 窗口尺寸预设 + 全屏（`F11`）+ 窗口策略在启动时用代码施加。
- **必须出现的自检**：`[Menu]`、`[FrontEnd]`。
- **别做**：不要把窗口设置写回 `project.godot`，也不要靠它设拉伸策略。

### M9 · 贴图与字体

- **做什么**：贴图导入管线 + `UnitArt` 的**三级兜底**（视图 → 贴图 → 色块）+ CJK 字体装载与缺字体回落。
- **必须出现的自检**：`[Art]`、`[Font]`。
- **目视项**：贴图在 60px 与 96px 两种尺寸下是否认得出。

### M10 · 花园（持久资产）

- **做什么**：花园存档 + **从花园召唤**（不是凭空造）+ 伤害账本与结算 + 重开键回滚 + 浇水/施肥 + 卡冷却。
- **必须出现的自检**：`[Garden]`、`[GardenUI]`。
- **关键不变式**：**战斗期间不改存档**——伤害先记账本，只有真正的战斗结束才落盘；重开是唯一的回滚路径。

### M11 · 经济与成长

- **做什么**：第二份存档（钱 / 仓库 / 背包）+ 仓库 / 商店 / 背包三页 + **钱只能靠卖** + 卷轴解锁与耐久
  + 通关奖励与首通 + 经验等级 + 天赋药剂 + 掉落。
- **必须出现的自检**：`[Profile]`、`[Items]`、`[Reward]`。
- **关键不变式**：**掉落的都是物品**，钱必须经玩家手动卖出。

### M12 · 语言层

- **做什么**：`Loc` + 按域拆分的文案表（每条中英成对、`%` 占位符数量与顺序一致）+ 设置页即时切换
  （**战斗中切换要就地改名，不重建节点**）+ 缺字体回落。
- **必须出现的自检**：`[Loc]`，以及"language switch"那条判据。
- **纪律**：玩家可见文案一律走语言层；日志与自检输出**永远是英文**。

### M13 · 音乐与音效

- **做什么**：曲目表 + 每个画面点名一首 + 交叉淡入淡出 + 循环双保险；cue 表 + 播放器池 + 去抖 + 长度闸门。
- **必须出现的自检**：`[Music]`、`[Sfx]`。
- **目视/听感项**：这一批**无头完全证明不了**，必须开窗口听一次。

### M14 · 数据表底座与图鉴

- **做什么**：CSV 读取器 + **分层装配**（子族 > 族 > 主表）+ 各花名册门面 + 图鉴页。
- **必须出现的自检**：`[Plants]`、`[Zombies]`、`[Skills]`、`[Items]`、`[Almanac]`。
- **关键判据**：表里的数**真的进了游戏**（接线判据：读到了就报 `overrides`，读不到回兜底并说明）。

### M15 · 单位扩面（玩法补齐）

- **做什么**：按家族成批加植物（射手 / 生产者 / 墙 / 抛掷 / 一次性 / 刺），僵尸侧补齐护甲与降级、
  处决线、暴怒、召唤、巨人前摇后摇；抛射与溅射。
- **必须出现的自检**：战斗探针逐族一组（`--battle=` 进入），每组都走**真路径**并在战斗区域之外跑。
- **纪律**：每株新单位都按 `PROMPT.md` §4.6 的必改点走；**每一句"特殊机制"散文要么有代码认领、要么被点名报账**。

### M16 · 战役

- **做什么**：局存档 + 章节图 + 事件表 + 编队 / 路线图 / 三选一 / 事件四页 + 罚金重试 + 归档回 meta。
- **必须出现的自检**：`[Chapter]`、`[Run]`、`[Events]`。
- **不要省**：`PROMPT.md` §6.4 那**五个预留点**——省掉它们，后三种模式就得重写核心。

### M17 · 耐久与债务治理（长期项，不是一次性）

- **做什么**：原子写盘与失败可见；把管理器按"**搬代码、留状态**"分刀；给验收加可编程的收尾；
  每条判据都做过反向验证。
- **必须出现的自检**：`[Save]`、`[Recover]`，以及崩溃/坏档路径的判据。
- **何时停止**：**永远不停**。这是每批顺手带一点的那类工作，不是"最后统一做"。

## 4. 内容扩面的顺序

- **先少量、后成批**：M1 只做 3 株植物 + 1 种僵尸；M15 才按家族成批扩。
- **加一种僵尸 = 加一行表 + 一条文案**（不改逻辑代码）；**加一株能上场的植物 = 按 `PROMPT.md` §4.6 的必改点逐条走**
  ——漏掉注册表那一处，它会**静默变成另一种植物**，所以那条判据必须在。
- **关卡**：先 1 关，再排到 8 关 + 1 条多路变体；排关卡前先算"火力天花板"（这局最多能打出多少伤害）。
- **道具**：先卷轴与钱币（它们撑起经济闭环），再上肥料 / 能量豆 / 药水。

## 5. 交付前的清单

1. §2 的验收命令：`FAILED` 为空，且每个模块前缀**逐个**都在打印 PASSED。
2. `--battle=` 探针全绿，并且**跑完前后两份存档逐字节相同**（探针不许碰玩家资产）。
3. 把窗口拖到 4:3 与 21:9、按 `F11`：几何自检每次重打印，六个采样比例零 FAIL。
4. 切语言（设置页或命令行覆盖）：战斗中单位名牌**就地改写**、不重建节点，`[Loc]` 无 FAIL。
5. **反向验证**：删掉一张贴图 / 把一个数字写成"三百" ⇒ 不崩；前者只在贴图自检里计数，后者让那一块自检变红。
6. 只写两行表 + 一条文案就加一种僵尸 ⇒ 它能出现在关卡里、能被召唤、能被打、能掉东西。
7. 把存档内容换成垃圾 ⇒ 它被改名留存为 `.bak`、游戏用默认档继续跑，恢复自检绿。

## 7. 无头证明不了的事（目视与听感清单）

下面这些**只能开窗口看**，所以不要假装它们被自检覆盖了。攒成一批一次看，结果记进 §6。

- **渲染**：切页是否干净、HUD 有没有重叠、卡片会不会撞到 END TURN、六种窗口比例、
  花园 / 图鉴 / 仓库的排布、贴图有没有错层。
- **手感**：每一拍之间的停顿是否可读、快进是否顺、动画是否真的不阻塞逻辑。
- **单位姿态**（规则见 `docs/prompt/FX.md`，数值 `BalanceUI.FX_*`）：被啃时是否**向后**歪、出手时是否
  **向前**歪，**转身的单位要跟着转过去**；空闲呼吸有没有在被特效压住之后接上（而不是跳一下）；
  乱斗里出手**只有前倾、没有前冲**（那是约定，不是 bug，见 `docs/prompt/FX.md` §7）。
- **近战图画**（[P110b/P110e]，`docs/prompt/FX.md` §8）：啃/砍中的那一下，挨打的那一点应当出现一张图画、
  约三分之一秒内淡出——**僵尸 = 爪痕，民兵 = 蓝白斩击，骑士 = 重斩，队长 = 金色圣斩**，
  盾兵只有火花（他那一格空着，是故意的）。看三件事：**图画对不对得上人**、
  同一个单位**连挨几下会不会糊成一片**（红闪 + 火花 + 图画是三层叠加）、
  **大小与角度**看着对不对。数值在 `BalanceUI.MELEE_FX_*`，用哪张图在表里（`近战特效` 列）。
  **乱斗**（[P110d]）同样有：近战一下必有火花，图画跟着attack方的表行走；
  远程命中不在此列（那是 `BrawlShot` 自己的爆环）。
- **三种远程attack**（[P110f/P110g]，`BRAWL.md` §8.9）：怪兽三件（激光眼 / 火焰眼 / 眼球塔）出手时应当
  分别出现**细光一闪 / 一个火锥 / 一根带亮环的粗光柱**，且**打完立刻掉血**（不飞、不延迟）。
  看这些：
  **① 形状能不能一眼分辨**；**② 颜色在草地上够不够亮**（数值全在 `BalanceUI.BEAMS`）；
  **③ 激光眼与火焰眼的光是"闪一下就没"**（端点只取一次，不追人），而**眼球塔的光要烧满约 3 秒**，
  跟着两个身体走、**目标死了会转火**、**两段通道之间约 1 秒不冒光**；
  **④ 眼球塔一次通道打掉的血**大致等于同一时间激光眼打掉的血（3 秒 6 跳 ≈ 3 次attack）——
  这是"这座塔值不值 4 费"的手感判断，数在 `BalanceBrawl.BEAM_TICK_*`。
  ⚠ 通道是**真的持续伤害**，所以目视时也顺便看一眼**血条是不是在稳定地掉**，而不是只有开头一下。
- **听感**：每个 cue 是否对得上发生的事、去抖是否自然、循环点是否听得出来。
- **可玩性**：一局是不是 §1 说的那个长度；第一次玩的人能不能自己看懂怎么操作。

## 8. 自检与排错（原 README「自检与排错」）

> 通过标准永远只有一条：**`FAILED` 一个都没有**。这一节是"看到某一行时该怎么办"。


每次启动都会跑一组自检，控制台里全部 `PASSED` 才算健康。和花园相关的两块是（前缀不同是 P52 拆开的：
**规则与存档 = `[Garden]`，页面几何 = `[GardenUI]`**，以前两块都叫 `[Garden]`，红字认不出是谁）：

- `[Garden]`：起始花园内容、存档读写往返（血量与濒死状态必须能读回）、损坏 JSON 的兜底、
  随机抽取**绝不会给出濒死或已上场的植物**、浇水/施肥的数值与拒绝条件、战斗结算写回；
- `[GardenUI] layout … (P25)`：花园页的**几何**自检（不用开界面）——4×4 花盆放得下且不压到右侧详情栏、
  格子大小在 `GARDEN_PLOT_MIN..MAX` 之内、**格子数 == `GARDEN_CAPACITY`**、右上角道具栏不出顶栏也不出边距、
  五行属性（名称/等级/生命/状态/天赋）不压到提示块、`BACK` 在面板内、**花盆与植物不压到格子上的文字**；
- `[SelfCheck] plant cards`：开局全卡 READY、**每回合卷轴额度开局是满的**、召唤确实取自花园
  （血量与 `#编号` 对得上）、**同一回合第二次召唤被拒**且额度下回合恢复、冷却真的会挡住卡片、
  **被拒绝时不消耗冷却/额度也不扣阳光**、自检用的探针不会污染花园账本；
- `[Layout]`：六种窗口比例下的棋盘几何，**外加"右上角按钮不出屏、不超出顶栏"**的断言；
- `[Levels]`（P26）：关卡包的发现结果——每个文件一行（波次数 / 僵尸数 / 关卡里用到的**僵尸种类**），
  **坏文件标 `BROKEN` 并写明原因**，被命名规则跳过的文件单独一行 `skipped:`；
- `[Plants]` / `[Zombies]`（P26）：两张单位数据表的自检——每行一条（植物：hp / attack / 费用 / 冷却 /
  成长列 / 贴图；僵尸：hp / 护甲 / 移动 / 啃食 / **啃脑伤害** / 贴图 + 已实装 / 仅展示的机制），
  外加一行**接线检查**：战斗解析出来的费用、冷却、生命、技能、基础僵尸数值**必须等于表里的值**
  （`wired True`）；表和 `balance.gd` 常量不一致时打印 `overrides Balance: hp 300->500` ——
  那是**正常的**（表本来就要覆盖代码），只有 `wired False` 才是 `FAIL`；
- `[Items]`（P27；**P88 改口径**）：道具表 `data/items.csv` 的自检——每行一条（分类 / `price` / 对应植物 / **贴图是否真的能加载**），
  外加**表优先**的接线检查：`Balance.item_*` 先问表、`ITEM_DEFS` 只是读不到表时的兜底，所以
  "表里的数字必须等于战斗里的数字"这条 FAIL 判据**已作废**（同一个数不再有两个业主），与 `Balance` 不一致只打印
  `overrides Balance`；**代码表里没有、只有表里有的行**打印 `sheet only`（阳光今天就是这种），也算 OK。
  **真正会判 FAIL 的是**：`ITEM_ORDER` 点名的 id 在表里没有行（战斗发得出、图鉴永远看不到），以及分类为空或贴图加载不出来；
- `[Almanac]`（P26/P27/P28）：图鉴页的**几何**自检（不用开界面）——每个名单（植物 / 僵尸 / 道具 / 关卡）
  都放得下格子、**每行正好 8 格**、页签行不压副标题也不压格子**且不比格子宽**、八个字段行 + 说明块 + `BACK` 全在详情栏内、
  **右上角贴图框在面板内且不压到说明块**、四个页签的文案不是 key 本身也不是彼此；
  （P28）**翻页**部分也一起审：每页容量 × 页数 ≥ 行数（一条不漏）、设计窗口下一页正好 **8 × 3 = 24 格**、
  这一页的格子**真的放得进格子框且没被缩小**（`scale 1.00`）、翻页条在最后一排格子下面且不出提示带；
- `[ItemUI]`（P22/P28，**P52 起与前一条分开命名**）另有一行 **`capacity_for` 对账**：一个"不缩小地放得下多少格"的容量函数必须正好是
  `fit_for()` 的分界（那么多格是满尺寸，多一格才开始缩）——图鉴的翻页就靠它；
- `[Events]`（P31-A）：事件表 `data/adventure/events.json` 的自检——每个事件一行（标题 / 选项数），
  坏 JSON、缺中英字段、选项里没有可解析效果的都会打印原因并 `FAIL`（事件节点会被章节加载器拒绝）；
- `[Chapter]`（P31-A）：战役章节的自检——`data/adventure/` 下章节文件的发现数、开局章节的节点概况、
  **全部节点可达 + 每个 battle/boss 节点都指向真实关卡 + 有且仅有最后一层是 BOSS**、
  未知节点名称的章节必须被拒绝；
- `[Run]`（P31-A）：局存档 `user://run.json` 的自检——指针推进与分支可选性、战败罚金**翻倍封顶 ×4**、
  限次 mod 用完自动消失、**保存→读回往返**（指针/小队/背包/罚金/mods 一条不少）、
  非法 mode / 小队垃圾条目 / 不存在的道具**大声降级**而不是崩溃（自检用探针文件，绝不碰真档）。
- `[SelfCheck] zombie types, armour, the 1/3 rule`（P26，**开一局时跑**）：拿真实单位验证数据通路——
  路障僵尸的数值来自表、**护甲先扣血后扣**、**破甲后变成普通僵尸**（名称 / 移动 / 处决规则都变）、
  普通僵尸在 `hp ≤ 1/3` 时立即死亡；
- `[SelfCheck] level data`：关卡 JSON 的字段解析与非法值兜底，包含 `cards` / `summons_per_turn` / **`music`** /
  **包格式的 `waves`（带 `type` / `count` / `cols` / `banner`，以及"未知僵尸名称被替换并报出"）**；
- `[Loc]`（P20）：语言词条本身——**每条都有中英两版**、**格式串占位符两种语言数量一致**、没有重名 key，
  并打印当前语言与字体的配对情况（选了中文但字体画不出汉字会明确写出来）；
- `[Loc] name helpers … = OK`（P20）：**接线**自检。逐条比对 `Balance.plant_name("peashooter")` 是否真的
  等于 `Loc.t("plant.peashooter")`（植物 / 道具 / 工具 / rarity / 天赋 / 难度共 7 组）。
  任何一处退回英文，它会打印"应该是 X，实际是 Y"并 `FAIL`——这就是"中文界面里植物名还是英文"的报警器；
- `[Music]`（P21）：29 条曲目的文件是否就绪（`NOT IMPORTED … FAIL` 就是素材被移走或没导入），
  外加游戏自己会用到的那 6 首的**时长、循环点**与 `loop=forward(...)` / `loop=0` 是否符合表里的设定；
- `[SelfCheck] language switch`（P20，**开一局时跑**）：拿一个探针植物把语言切一遍（中 → 英 → 中），
  断言**棋盘上的单位被就地改名**（同一个实例，不是重建棋盘）、**HUD 按钮文字真的跟着换**、
  最后语言还原成开局那一种。它和另外几组自检一样只在**开局 / 按 R** 时运行。

### 语言层排错（P20）

| 现象 | 先看什么 | 处理 |
|---|---|---|
| 中文界面里**植物/道具名还是英文**（例如卡片写 `Peashooter`） | 启动横幅里 `[Loc] name helpers … = OK` 还是 `FAIL` | `FAIL` = 名称函数所在文件被换回了旧版本（最常见原因：**编辑器用旧缓冲区把文件覆盖了**）。在编辑器里对 `balance.gd` / `difficulty.gd` 选 **Reload**，或关掉重开；必要时用版本控制找回 |
| 中文全部变成英文，但界面不报错 | `[Loc] UI font:` 那行是否 `CJK ok` | 字体没被识别时**所有文案整体回落英文**（刻意设计，避免豆腐块）。字体是**外部资产、不打包进 git**（见 `README.md`「外部资产」），clone 后需自备一个 CJK `.ttf`/`.otf` 放进 `assets/fonts/` 并让编辑器导入 |
| 某个界面出现 `ui.xxx.yyy` 这样的原文 | 启动有没有 `[Loc] no string for key` 警告 | 该 key 在文案表里不存在（拼错或被删）。按 §3 的四个表文件补一条中英双语词条 |
| 出现 `[Loc] key 'x' has 2 placeholder(s) in zh but 3 in en | FAIL` | 该词条两种语言的 `%s`/`%d` 数量不一致 | 补齐占位符（两种语言必须数量与顺序一致，Godot 的 `%` 没有位置写法） |

### 音乐排错（P21）

| 现象 | 先看什么 | 处理 |
|---|---|---|
| **完全没声音** | 启动有没有 `[Music] NOT IMPORTED …` 或 `[Music] cannot load …` | 素材被移走、改名或没导入。音频是**外部资产、不打包进 git**（见 `README.md`「外部资产」），clone 后按 `assets/audio/readme.md` 清单自备 `.wav` 放进 `assets/audio/`，让编辑器导入完再 `Project > Reload Current Project` |
| 有声音但**放一遍就停** | 控制台有没有 `[Music] … does not loop natively (…)` | 有这行=**兜底循环在工作**（会自己接上，接缝极小）；如果连这句都没有且确实只放了一遍，把 `[Music] playing …` 那几行贴回来 |
| **声音忽大忽小 / 卡顿** | `[Music] playing …` 是否在同一画面里反复出现 | 反复出现说明某个画面在每回合重复点歌（`Music.play` 对同一首是空操作，正常不会重复打印） |
| 设置页的 `音量：xx%` 与听感不符 | `[Settings] loaded …` 那行的 `music=on 70%` | 音量是**线性值换算成 dB**，100% = 0 dB；日志与按钮都按百分比显示 |
| 想临时静音玩一局 | — | 设置页点一下 `音乐：开` 变 `音乐：关`（战斗中也能点，入口是右上角 `设置`） |

> **想让自检在无窗口环境里跑出来**（含"开一局"才会跑的那几组）：
> `godot --headless --path . --quit-after 400`；只看语言层可以加 `-- --lang=zh` / `-- --lang=en`。
> 按 `AGENTS.md` 的约定，**命令由你执行**（AI 不跑）。

出现 `FAIL` 时先看那一行提示的断言，再对照 `scripts/balance/balance.gd` 里的对应常量。
协作与交付约定（AI 不执行命令等）见工程根目录的 **`AGENTS.md`**。
