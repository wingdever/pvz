## 1. 棋盘与回合模型

### 1.1 棋盘

棋盘的常量（窗口、格子边长、列数行数、可用行、脑子区宽度）业主是 `scripts/balance/balance.gd`
与 `project.godot`——**本文件不抄那张表**。这里只留设计意图：

- **格子是正方形，边长按窗口算**（不是写死的像素），所以任意比例下草坪都居中且不满溢。
- **关卡自己声明启用哪几行**：单路关是"竖切"，不是"删掉四行"——同一个棋盘能演两种关。
- **脑子区不是一格，是最左列左侧的一条预留带**：僵尸贴脸时才啃得到脑子，玩家有反应时间。

### 1.2 回合顺序

回合的状态机与判定顺序是**规则**，写在 **`PROMPT.md` §3.1**
（TURN_START → OPERATION → PLANT_ACTION → ZOMBIE_ACTION → TURN_END → WIN/LOSE）。要点只有三条：

1. **植物先手**：同回合里植物先结算。
2. **新入场的僵尸当回合不行动**，但会被当回合的植物打。
3. **工具是操作阶段的即时行动**，不经过任何充能条。

### 1.3 行动点（早期"行动条"已被取代）

早期版本给每个单位一条**行动条**（每回合 +1、涨满即行动）；**现行模型是行动点（AP）**：
每个单位在自己那一拍起手拿固定点数，每次出手花掉该技能自己的价格，**用不完作废、不跨回合累计**。
规则见 **`PROMPT.md` §3.2**，技能价格在 **`data/units/skills.csv`** 的「技能消耗AP」列。
本文件不复述这两处。


## 2. 战斗节奏的推导（数值不在本文件）

### 2.1 单位数值

**植物的 HP / 费用 / 输出 / 技能价，僵尸的 HP / 护甲 / 移动 / 啃食 / 啃脑伤害**，
一律以 **`data/units/*.csv`** 为准（分层装配：子族 > 族 > 主表）；
**等级成长**在表的「HP成长 / 技能成长 / 天赋加成」列，**关卡缩放**在 `data/level/*.json`。
本文件不再抄第二份——抄一份就多一个业主，多一个业主就先烂。

### 2.2 为什么这些数长这样

三条推导原则（它们才是本文件该留下的东西）：

1. **僵尸的等效血量要按"处决线"打折**：普通僵尸低于三分之一血即死，所以它的有效血量约为名义值的 2/3。
2. **植物火力按"一回合能打几下"算**：技能价决定每回合出手次数，费用决定开局能不能立刻放下来。
3. **护甲是血之前的一层**：带甲僵尸的等效血量是"护甲 + 打折后的血"，不是两者简单相加。

据此：一张表算完"一株豌豆要几回合才能杀掉某种僵尸"——这才是排波次要看的量。

### 2.3 派生量（用 `data/` 里的数现算）

| 派生量 | 计算 | 结果 |
|---|---|---|
| 豌豆伤害/阳光 | 20 / 100 | 0.20 |
| 普通僵尸有效 HP | 270 × 2/3 | **180** |
| 豌豆击杀普通僵尸 | 180 ÷ 20 | **9 回合** |
| 路障僵尸有效 HP | 270 × 2/3 + 250 | 430 |
| 豌豆击杀路障 | 430 ÷ 20 | 21.5 → **22 回合** |
| 铁桶僵尸有效 HP | 270 × 2/3 + 600 | 780 |
| 豌豆击杀铁桶 | 780 ÷ 20 | **39 回合** |
| 铁门僵尸有效 HP | 270 × 2/3 + 500 | 680 |
| 豌豆击杀铁门 | 680 ÷ 20 | **34 回合** |
| 橄榄球有效 HP | 600 × 2/3 + 300 | 700 |
| 豌豆击杀橄榄球 | 700 ÷ 20 | **35 回合** |
| 巨人 HP | 1500 | 1500 |
| 豌豆击杀巨人 | 1500 ÷ 20 | **75 回合** |
| 僵尸入场→col 0 | 入场闲置1 + 6格 × 3 | R+19 开始啃脑 |
| 僵尸啃光脑子 | 100 ÷ 10 | 28 回合 |
| 僵尸咬死豌豆 | 300 ÷ 100 | 3 回合 |
| 僵尸咬死坚果墙 | 1000 ÷ 100 | 10 回合 |
| 向日葵回本 | 第2次产出 | 5 回合 |

### 2.4 位置悬崖（普通僵尸）

| 豌豆位置 | 首次咬击 | 击杀 | 结果 |
|---|---|---|---|
| col 0 | R+16 | R+8 | ✅ 余量8 |
| col 1 | R+13 | R+8 | ✅ 余量5 |
| col 2 | R+10 | R+8 | ✅ 余量2 |
| col 3 | R+7 | R+8 | ⚠️ 咬1口，安全 |
| col 4 | R+4 | R+8 | ❌ 豌豆R+6死亡 |
| col 5 | R+1 | R+8 | ❌ 豌豆R+3死亡 |

**含义**：有效安全区 **col 0~3**；col 4 起必死。

### 2.5 多僵尸同格

- 僵尸可重叠，前压的挡住去路，后面的挤到 `col = 前一只 - 1`，然后一起咬。
- 2 只同时咬一株豌豆 = 200 伤/回合 → 豌豆 2 回合没；坚果墙 5 回合。
- 排多僵尸波次时按「胃口的倍率」算，不按只数线性算。

### 4.3 融合

**规则写在 `PROMPT.md` §3.9**（基座 + 叠种 = 产物；数值取较高者；花费为两者之和；经验合并、战斗结束拆回）。
**哪两种能合成什么**属于数据，本文件不维护那张表。

设计意图（留档）：融合让"重复抽到的同族植物"变成**升级路径**而不是只能卖钱；
"战斗结束拆回"是为了让花园里那**两株原植物**继续各自累积经验，
不产生一个只在局内存在、回不了花园的新资产。

## 5. 工具

三件工具（铲 / 手套 / 锤）与"充能"模型的**规则见 `PROMPT.md` §3.4**；
**每个工具的充能阈值由关卡数据决定**（`data/level/*.json` 的 `tools.<id>.threshold`），
代码里只留读不到关卡时的兜底值。

设计意图（留档）：铲子与手套是**救急工具**（低阈值，一局能用好几次）；
锤子是**清场工具**（高阈值，一局用一两次，用来处理"防线已经破了"的那一格）。
**锤子没有列 / 行限制**——限制它只会让玩家在真正需要的时候发现它够不着。

## 7. 僵尸机制细节

### 7.1 护甲

- 独立 HP 层，先扣护甲再扣 HP。
- 不免疫控制（冻结、眩晕仍生效）。
- 破甲时播放“碎裂”提示。

### 7.2 撑杆跳

- 遇到第一株植物时不咬，直接跳到植物左边一格。
- 跳过之后变普通僵尸（移动 3，啃食 100）。
- 一局只能跳一次。

### 7.3 读报暴怒

- 报纸被打掉后进入暴怒：移动 3→1，啃食 100→150。
- 不可逆。

### 7.4 铁门

- 门只挡**直线射弹**：沿直线飞过来的豌豆一类先被门接住（护甲 500 挡在血前面），
  连这类射弹附带的特殊效果（冻结、击退）也一并被挡。
- **不是直线射弹的东西门一律不管**，直接扣血：抛物线（西瓜、卷心菜）、一次性爆炸
  （樱桃 / 火爆辣椒 / 土豆地雷）、地刺、铲子。（[P77] 这条从前只写在"豌豆"上，代码却什么都挡。）
- 从背后命中（源单位 col 更大，如裂荚射手）无视护甲。
- 门被打掉（护甲归零）之后上面几条同时失效，但铁门僵尸**不**降级为普通僵尸。

### 7.5 舞王召唤

- 每 7 回合召唤 1 只伴舞。
- 伴舞 HP = 135，移动 4 回合 1 格，不掉落。
- 舞王本身不attack。

### 7.6 巨人投掷与锤击

- 入场时投掷 1 只小鬼到第 3 列。
- 小鬼落地后立即行动。
- **锤击**：3 回合前摇 → 执行（摧毁该格所有植物）→ 2 回合后摇。
- 前摇期间可被锤子/樱桃/大嘴花处理；后摇期间不能移动。
- 免疫冻结，不免疫锤子。

### 7.7 气球飞行

- 地面植物（豌豆、坚果、大嘴花）无法attack。
- 只有三线射手、机枪射手、寒冰射手能打。
- 气球被打掉后落地，变普通僵尸。

### 7.8 雪人僵尸

- 每波僵尸超过 5 只时，5% 概率替换 1 只。
- 不attack，每回合向左 1 格。
- 走到最左后转身向右，转身期间仍可被击杀。
- 走到最右后消失。
- 击杀后必定掉落 1 枚钻石。

## 10. 花园与养成

### 10.1 容量

| 项目 | 值 |
|---|---|
| 容量 | 16 个花盆（4×4） |
| 初始阵容 | 1 株 1 级豌豆射手 |
| 召唤规则 | 从同名称可用实例随机抽一株 |

### 10.2 倒地恢复

| 方式 | 代价 | 结果 |
|---|---|---|
| 浇水 | 免费、无限 | 回 50% 最大 HP（倒地不能浇水） |
| 施肥 | 1 袋化肥 | 解除倒地 + 回 50% HP |
| 自然恢复 | 免费，等 | 回 10% HP |

自然恢复时长 = `60 s × rarity系数 × (1 + 0.3 × (等级−1))`

| rarity | 系数 | Lv1 | Lv5 |
|---|---|---|---|
| common | 1.0 | 60 s | 132 s |
| uncommon | 1.5 | 90 s | 198 s |
| rare | 2.5 | 150 s | 330 s |

### 10.3 等级与经验

**规则见 `PROMPT.md` §6.3**：谁补刀谁拿经验、升级抬高生命上限并补差额、
技能数值是**每株实例**的属性（所以 3 级的豌豆射手真的更疼）。

**数字不在本文件里，公式在 `docs/NUMBERS.md` §4**：一条曲线 `基础值 × (1 + 成长率 × (L-1))`，
**三维**（生命 / attack / 防御，[B11] 起防御是第三维），成长率在 `data/units/plants.csv` 的
「HP成长 / 技能成长 / 防御成长」列（`Balance.PLANT_*_GROWTH` 是兜底），经验阈值是
`Balance.exp_to_next_level`（`EXP_PER_LEVEL × L`）。本文件不再列等级收益表——那张表会随成长率漂移。

> **为什么防御成长比另外两条缓**（[B11c]）：防御在伤害公式里是**分母上的刻度**（`128/(128+防御)`，`NUMBERS.md` §3），
> +10%/级 等于每级再削掉一成伤害；+8% 是首版，手感旋钮在表里而不在公式里。

### 10.4 天赋药剂

- 每株植物限一次，永不叠加。
- 豌豆/向日葵：技能 +50%
- 坚果墙：最大 HP +50%

## 11. 波次结构

### 11.1 JSON 格式

```json
"waves": [
  {
    "id": 1,
    "start_round": 1,
    "spawns": [
      { "round": 1, "type": "zombie", "count": 1 }
    ]
  },
  {
    "id": 2,
    "start_round": 8,
    "spawns": [
      { "round": 8, "type": "zombie_cone", "count": 1 },
      { "round": 12, "type": "zombie", "count": 2 }
    ]
  },
  {
    "id": 3,
    "start_round": 18,
    "spawns": [
      { "round": 18, "type": "zombie_bucket", "count": 1 },
      { "round": 22, "type": "zombie", "count": 3 }
    ],
    "banner": true
  }
]

11.2 字段
字段	含义
id	波次编号
start_round	波次从第几回合开始
spawns	生成事件列表
spawns[].round	第几回合生成
spawns[].type	僵尸名称
spawns[].count	生成几只
spawns[].cols	可选，指定入场列
banner	是否显示“一大波僵尸”提示

11.3 生成规则
到达 spawns[].round 时，按 count 在 spawn_cols 里从左到右找空格。
空格不足时，多余僵尸延后到下一回合。
同一回合多个 spawns 按数组顺序依次生成。
波次之间没有强制间隔，可以重叠。
