## 1. 一句话

给每个实体一条"贴地投影"（逻辑影子）和一个"高度区间"：判定**先 XY、再高度**，两道门都过才挨打。
收益是一整类以前不存在的玩法——**抛射越过前排砸后排、浮空单位低头躲平射、俯冲压高度躲弹道**。

逻辑影子（Logic Shadow）
├── 承载 z_height / z_velocity / z_gravity / z_thickness
├── 承载 body_width / body_depth / body_xoff / body_yoff（XY 平面碰撞形状）
├── 位置 = 世界中的 XY 平面位置（地面投影）
├── 是唯一参与 XY 碰撞检测的实体
├── 缺省形状由素材纹理整体尺寸推算（素材设计基准 128px = 1 格，见 §6）
├── 表值 `body_*` 权威，素材只供缺省
├── 不渲染，或只用于调试
└── 射弹与单位共用同一套参数与解算逻辑（`HeightBody`）

视觉影子（Visual Shadow）
├── 跟随逻辑影子的 XY
├── 形状 = 本体素材的 ink（中心 = ink 底边＝实测脚底、宽 = ink 宽）
├── 地面纵深 = 宽度的一半（= body_depth = body_width / 2 那条占地算法，D99）
├── 再按 z_height 等比缩小、变淡（同一曲线）
├── 不参与任何碰撞
└── 纯表现，用来反馈抬升高度

精灵（Sprite）
├── 跟随逻辑影子的 XY
├── Y 偏移 = -z_height
├── 视觉高度对应 z_thickness（命中高度区间）
├── 不参与 XY 碰撞
└── 纯表现，是逻辑影子抬升后的渲染结果

高度判定
├── z_height：脚底离当前地面的高度，向上为正（cell）
├── z_thickness：实体在高度轴上的厚度（cell），缺省 = 实测 ink 高 / 128（D112 定尺，**D113 摘掉那条 1.0 格地板**；量不到素材才答"全身高"兜底）
├── 高度区间 = [z_height, z_height + z_thickness]
└── 命中条件 = XY 重叠 + Z 区间重叠

碰撞流程
├── 第一步：逻辑影子在 XY 平面重叠（由各条路径现有的解算回答）
├── 第二步：比较双方高度区间是否重叠
│      a.z_height < b.z_height + b.z_thickness
│      AND
│      b.z_height < a.z_height + a.z_thickness
└── 两者都满足 → 有效命中

核心原则
├── 逻辑影子是碰撞实体
├── 视觉影子只是高度反馈
├── 精灵只是渲染表现
├── 先解算 XY 碰撞，再解算 Z 轴高度
└── 精灵高度 = z_thickness，视觉与判定保持一致（[B37] D113 起这句才是字面成立：判定读的就是素材画出来的那段高）

## 2. 三实体（形状来自用户 2026-10-06 定稿）

### 2.1 逻辑影子（Logic Shadow）＝碰撞实体

| 属性 | 规定 |
|---|---|
| 它是什么 | sim 里的一条数据：`{地面XY, z_height, z_velocity, z_gravity, z_thickness, body_width, body_depth, body_xoff, body_yoff}`。本项目里它是 **sim 里的数据**（乱斗 = `BrawlActor` / `BrawlShot` 持有的 `HeightBody` 实例），**不是 Godot 物理节点**——brawl 没有物理引擎，XY 重叠由现有的几何解算（点到线段距离 / 到达半径）负责。**"承载 CollisionShape2D / Area2D 或其它进行解算的对象"是泛化口径**：逻辑影子 = "谁解算 XY 重叠，谁就是它"，数学实质不依赖运行时 |
| 位置 | 地面投影的 XY（cell），**权威位置**——高度不改变"我站在哪" |
| XY 形状 | `body_width` / `body_depth` / `body_xoff` / `body_yoff`（cell）；缺省由素材纹理整体尺寸推算，表值权威 |
| 渲染 | 不渲染（至多调试可见） |
| 地位 | **唯一参与碰撞检测的实体** |

#### 2.1.1 `body_*` 四参数的语义

| 参数 | 语义 | 单位 | 缺省 |
|---|---|---|---|
| `body_width` | XY 平面碰撞体宽度 | cell | 素材纹理宽 / 128 |
| `body_depth` | XY 平面碰撞体纵深 | cell | `body_width / 2` |
| `body_xoff` | 相对"素材底部中心点"的 X 偏移 | cell | 0 |
| `body_yoff` | 相对"素材底部中心点"的 Y 偏移 | cell | 0 |

**坐标系**：按 Godot 2D —— **Y 向下为正**。`body_xoff` 定义在**素材局部坐标系**中，数据只写一个值、不镜像；`face_left` 时实现乘 `facing_sign`，翻转素材的同时翻转逻辑影子。

**`body_*` 与 `z_*` 的关系**：两者是**同一 sim 数据的两个维度**，同放 `HeightBody`：
- `body_*` 管 XY 平面的占地形状；
- `z_*` 管高度轴的区间。

**XY 平面碰撞的"2D 碰撞厚度 = 宽度 / 2"** 由 `body_depth` 表达；与高度轴的 `z_thickness` 无任何关系，两者不得混称。

### 2.2 视觉影子（Visual Shadow）＝高度反馈

跟随逻辑影子的 XY；**锚点与宽度来自本体素材的 ink**（[B36] / D111：中心落在 ink 底边 = 实测脚底，
不再是"画布底边"那个猜测；宽 = ink 宽），**地面纵深 = 宽度的一半**（与 D99 的
`body_depth = body_width / 2` 同一条占地算法，影子不许声称一个身体不会被击中的地面形状）；
再随 `z_height` **等比缩小、变淡**；不参与任何碰撞；纯表现。
**它是高度轴的前提而不是点缀**：画面 y 轴已被场地纵深占用，高度也沿 −y 向上画，
没有贴地的影子，玩家分不清"它飞高了"还是"它走上了一行"。
**贴地单位常驻影子**——影子是"地面锚点"的视觉常量，不是"浮空时才出现的点缀"；
只有常驻，跳起时缩小变淡才有对照基准。

### 2.3 精灵（Sprite）＝抬升后的渲染

跟随逻辑影子的 XY；屏幕 Y 偏移 = −`z_height` × `cell()`；视觉高度对应 `z_thickness`；
不参与 XY 碰撞；纯表现。

⚠ **推导方向分两种情形（用户 2026-10-06 定稿）：**

| 情形 | z_thickness 来源 | 渲染 |
|---|---|---|
| 表里留空 | **素材驱动判定**：`实测 ink 高 / 128`（D112 定尺，**D113 摘掉地板**——身体够多高由它自己画的东西答） | 素材原尺寸，天然一致 |
| 表里写了 | **表值覆盖**，判定以表值为准 | 渲染跟随表值（素材可能被缩放） |
| 连素材都没有 | 代码兜底"全身高" `UNIT_Z_THICKNESS_CELLS`（= 1.0 格，D113 之后**只在这一格说话**） | 平面占位形 |

**三种情形下视觉与判定一致，但推导方向相反。** 缺省时"美术是主基调"；显式值时"判定是业主"。
**表里写了数 ⇒ 判定不读素材**（与 S2/D73"窗口比例不改变 sim"同族：素材尺寸也不改变 sim 的显式值口径）；
**表里留空 ⇒ 判定读的是缺省推算**，而那条推算本身就是"以美术为主基调"的授权。
⚠ **[B37] 把 D104 的"自觉例外"收回来了**：那条 `max(…, 1.0 格)` 的地板当年是为了守"旧表 ⇒ 逐帧不变"
（现有素材按 96 基准画，裸 `/128` 会让"素材尺寸"静默偷改命中）。**D112 把尺子换成实测 ink 之后，地板成了唯一答题者**——
128 画布的素材里 ink 高恒 ≤ 画布高 ⇒ `max()` 永远答 1.0，"以美术为主基调"退化成一句空话，
而且它**系统性高估**了每一只画得比一格矮的身体。用户 2026-10-09 拍板摘掉（**D113**）。
⚠ **摘掉之后这条轴不再有安全网**：一只身体画得矮，就真的够不到平射的高度区间（乱斗的直行弹道是 `[0.45, 0.70]` 格，
`BalanceBrawl.SHOT_Z_CELLS`）。这是 D113 的**代价**，不是漏洞：要一只身体矮到能钻过去，就让它**用表值表达**
（写 `z_thickness`，或给射弹写 `z_height`），别指望兜底。 roster 从来没在这条轴上量过（地板把问题抹平了），
所以"每个地面单位都吃得到平射"要**第一次靠眼睛确认**——见 `docs/dev/HEIGHT.md` §11-5 目视项 5。

## 3. 高度判定

```
z_height   脚底离当前地面的高度，向上为正（cell）
z_thickness 实体在高度轴上的厚度（cell）
高度区间   [z_height, z_height + z_thickness]
命中       XY 重叠 ∧ Z 区间重叠
Z 区间重叠  a.z < b.z + b.th  ∧  b.z < a.z + a.th（双侧严格小于）
```

**Z 区间就是"对空/对地"本身**——ground / air / diving 不是枚举状态，
而是从区间自然派生：贴地区间够不到高空、俯冲就是 `z_velocity` 把区间压下来。
数据表因此只加高度两列，不加任何"飞行标签"。

## 4. 碰撞流程（两道门）

1. **第一步：XY 重叠**——由各条路径现有的解算回答（乱斗的 swept 点线段、到达半径、近战触及）；
2. **第二步：高度区间相交**——新增的第二道门，比较**双方**的区间。

两者都满足 ⇒ 有效命中。**XY 过了而 Z 没过 = 打空**——O44 口径向高度轴延伸：
没有伤害、没有命中音、没有爆环、没有日志。

## 5. 抛射物也有 Z 区间【本轮拍板】

- **旧 doctrine 作废**：`docs/prompt/BRAWL.md` §8.7.2 与弹道注释里"抛射的抬升是纯装饰、
  地面航迹才是判定、lobbed 永不早于直线命中"——用户 2026-10-06 点板：
  **`_lift` 从装饰升级为权威**，射弹的当前高度参与命中。
- 三条轨迹各自的 Z：
  | 轨迹 | Z 怎么飞 |
  |---|---|
  | 直线 / 追踪 | **恒定巡高**（表列；兜底 0.45 cell ≈ 齐胸——它能命中贴地单位的 [0,1]，也会被高浮空躲过） |
  | 抛射 | 起止 `z = 0`，中段 `z(t) = 顶点 × 4t(1−t)`（顶点表列；兜底 **0.5 cell**——按素材设计基准 128 由旧 64px 顶点换算而来，随棋盘缩放、与弹速同族 D73）；越过谁、砸到谁由区间决定 |
- 命中、穿透扫掠、溅射三处都走 Z 门。
- 意义：不给射弹 Z，高度轴只对近战生效，"抛射越顶 / 浮空躲平射"全落空——这条是本轮
  "高度轴值不值得引入"的真正答案。

**射弹与单位共用参数与解算**：`BrawlShot` 与 `BrawlActor` 各持一个 `HeightBody` 实例；
`z_overlap` 是共用静态函数；XY 命中仍走原有几何（点到线段距离），Z 门是第二道。
**射弹的 `body_*` 缺省**：有 SVG 素材按素材纹理整体尺寸推算（纹理 px ÷ 128，§6 的素材设计基准）；无素材则 `body_width = SHOT_HIT_RADIUS × 2`、`body_depth = 0`。

## 6. 口径：全链路 cell

`z_height / z_thickness / z_velocity / z_gravity / body_width / body_depth / body_xoff / body_yoff`
在 sim 与数据表里一律是 **cell**；像素只在渲染边界换算。

**两把尺子，各司其职：**

| 尺子 | 值 | 用途 |
|---|---|---|
| 素材设计基准 | **128px = 1 格** | 素材 → cell 的换算（`纹理px / 128`），固定、与窗口无关，判定稳定性业主 |
| 运行时 cell | `BrawlField.cell()` = 动态 | cell → 像素的换算（`z_cell × cell()`），由 `BrawlLayout` 从窗口反推，S1 唯一尺子 |

**素材侧换算与渲染侧换算走两把尺**：前者锁死 128 保证判定跨窗口稳定；后者走 `cell()` 保证影子/抬升/场地永远同步。
两把尺的比值（`cell() / 128`）只出现在"素材显示尺寸"上，不进入任何 sim 判定。

⚠ **不钉死 `BrawlField.cell()`**：它是 `BrawlLayout` 由窗口反推的动态值（S1"唯一尺子"与 S2/D73 的业主）；
钉死 128 会纵向溢出（默认窗口下 ≈ 856 > 720），且破坏窗口自适应。这是另一批布局改革，本期不做。

⚠ **常数按 cell authored**：`LOB_APEX_CELLS = 0.5` 等值照常按 cell 定义，弧高随棋盘缩放——与弹速同族，是 D73 的正解。
所有从旧 96 基准推导的 cell 常量（尤其 `LOB_APEX_CELLS`：0.7 → 0.5）在实现时按新口径重估；实现文档 §3-9 与 §11-5 已登记。
> **[B18 改口（2026-10-06，D106）]**：抛射**兜底**顶点不再是固定 `LOB_APEX_CELLS = 0.5`，改为**按射程取比例**
> `LOB_APEX_SHARE = 0.16`（出射角恒 ≈33°，远近同调）；`z_height` 一格**写了数就仍是固定顶点权威**，本条上面那句只对留空的行成立。
> **[B19 补记（2026-10-06，D107）]**：抛射的**到达**多了一种结局——`projectiles.csv` 新列 `溅射半径` 写了数的行，
> 落点没人也**起爆**（O44 不破：炮弹碰到了地）；爆炸发生在 z=0，爆伤照过本规格的 Z 门（浮空者不挨炸）。形状见 `BRAWL.md` §8.17。

## 8. 渲染规则

- **排序与遮挡永远按逻辑影子 Y**（地面投影），不按抬升后的精灵 Y——跳起来的人不该突然抢到前排；
- 浮空身体整体抬到地上身体之上（`z_index` 常数，仍在 FX 之下）；
- HP 条与伤害飘字跟精灵走（抬升后），视觉影子在 pieces 之下的独立道；
- **贴地单位也画视觉影子**（常驻，用户 2026-10-06 拍板）——影子是"地面锚点"的常量；
- **影子 = 贴地椭圆**：底边 = **本体素材实测 ink 底边**（脚底）、宽 = ink 宽、**纵深 = 宽的一半**（D111），再随高度**等比缩小、变淡**（曲线常数与那条"一半"归 `BalanceUI`，[B36] 起旧的"宽度占格比例"与"压扁比"**两个常数都没了**）。
- **脚底只有一条线**（[B37] / D114）：影子锚点、倒地翻倒的轴心、空闲拉伸与受击果冻的压脚点，**全部读同一个实测值**（身体实际画出的墨迹底边）。以前这三处里后两处用的是"画布底边 = 半个盒子"的猜测，比真实脚底低约 1/8 个盒子，于是会出现"影子贴在脚下、身体却在空转半格"的错位。**没有素材可量时**（缺文件 / 读不到像素）三者一起回**创作契约**那条线。

## 9. separation 高度感知

两个单位的 Z 区间不相交 ⇒ **不产生避让力**——一个跳在空中的身体不该把旁边的地面单位挤开。
（推挤、击退仍作用于地面 XY，与高度无关。）
